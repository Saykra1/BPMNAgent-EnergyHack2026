# BPMN Agent — ИИ-помощник: текстовое описание процесса → BPMN 2.0

Аналитик описывает бизнес-процесс обычным текстом, а ассистент строит BPMN-диаграмму: пул и дорожки
участников, задачи, ветвления, параллельные шаги, циклы доработки и обмен сообщениями с внешними
организациями. Результат — `.bpmn`-файл, который проходит проверку по XSD-схеме BPMN 2.0 (OMG) и
открывается и редактируется в bpmn.io. Схему можно дорабатывать в диалоге («добавь согласование
юристом»), при этом ручные правки на холсте сохраняются.

LLM не пишет XML. Модель составляет JSON-план процесса и генерирует **Python-код на программном
интерфейсе `DIAGRAM`**. Всё остальное делает детерминированный код без LLM: песочница с AST-фильтром,
семантический валидатор, раскладка с пулами и дорожками, сериализатор и проверка по XSD.

## Быстрый старт

Все команды выполняются **из корня репозитория**.

```powershell
# Windows (PowerShell / cmd)
copy .env.example .env        # укажите LLM_PROVIDER / LLM_API_KEY / LLM_MODEL (можно позже)
.\run.bat                     # pip install + сервер → http://127.0.0.1:8080
# или вручную:
python -m pip install -r requirements.txt
python -m uvicorn server:app --reload --reload-dir backend --host 127.0.0.1 --port 8080
```

```bash
# Linux / macOS
cp .env.example .env && ./run.sh
```

Нужны Python 3.10+. Node.js нужен только для eval-проверки в bpmn-js и рендера PNG
(`tools/`). Docker: `docker build -t bpmn-agent . && docker run -p 8000:8000 --env-file .env bpmn-agent`.

Проверка подключения к LLM: `python scripts/check_llm.py`. Скрипт покажет, какой `.env` прочитан, и сделает пробный запрос.
Правка `.env` подхватывается без перезапуска сервера.

Проверка без LLM: откройте http://127.0.0.1:8080 и нажмите «Открыть демо-процесс» на холсте.
Можно также выбрать другой пример слева → «Открыть готовую схему примера».
Схему можно двигать на холсте, открыть «Инструменты» для ручного редактирования, скачать .bpmn
и открыть его на https://demo.bpmn.io. Проверки и автоматическая раскладка блоков находятся в меню «Ещё»;
результаты проверок, карточки шагов, связи и история — в панели «Анализ». При наведении на кнопки
и при фокусе с клавиатуры появляются краткие пояснения.
Кнопка «Найти шаг» ищет действия и события по названию (Ctrl+K) и позволяет выделить только шаги
выбранного участника. Поиск и фокус меняют лишь отображение: они не меняют BPMN-файл. Кнопка
«Вся схема», «К началу» и управление масштабом находятся внизу рабочего поля. Над схемой
показаны её название, число действий и результат проверки; после ручных правок проверка обновляется.

Выделенные фразы слева связаны с шагами схемы: наведите курсор или нажмите фразу, чтобы подсветить
и найти шаг. Нажатие на шаг возвращает к соответствующей фразе; на телефоне связи можно листать
стрелками или горизонтальным жестом. Вкладка «Связи» показывает шаги и фрагменты текста без
точной цитаты и позволяет привязать фрагмент к выбранному шагу. Привязки сохраняются в `.bpmn`.
«История» возвращает предыдущие версии схемы; до 20 версий хранятся в текущей вкладке браузера.
Кнопка «Создать схему» по умолчанию строит результат без уточняющих вопросов. Режим можно поменять
кнопкой «Режим: Без уточнений» под ней. После построения кнопка «Сверить текст и схему · Jev» слева
запускает дополнительную смысловую проверку привязок; её результат открывается в «Анализ → Связи».

Без ключа LLM интерфейс тоже работает: можно открыть сохранённые примеры, импортировать любой
`.bpmn`, править код схемы и пересчитывать раскладку.

**Провайдеры LLM**
- `LLM_PROVIDER=anthropic`: Claude через официальный SDK. По умолчанию модель `claude-opus-5-5`,
  `LLM_EFFORT=low`.
- `LLM_PROVIDER=gemini`: Google Gemini через нативный API (`generateContent`). Ключ берётся в
  https://aistudio.google.com/apikey, модель по умолчанию `gemini-2.5-flash`. `LLM_BASE_URL`
  указывать не нужно.
- `LLM_PROVIDER=openai`: любой OpenAI-совместимый Chat Completions API (OpenAI, vLLM, Ollama,
  LM Studio, OpenRouter, шлюзы к GigaChat/YandexGPT). Задайте `LLM_BASE_URL` и `LLM_MODEL`.
  Для прежней Claude Opus через OpenRouter: `LLM_BASE_URL=https://openrouter.ai/api/v1`,
  `LLM_MODEL=anthropic/claude-opus-5.5`, ключ OpenRouter в `LLM_API_KEY`.
- `JEV_ENABLED=true` включает необязательную проверку Jev. Её можно запустить кнопкой
  «Сверить текст и схему» под описанием или во вкладке «Связи». Она отправляет цитаты и названия шагов в OpenRouter Decisions API тем же ключом и
  показывает сомнительные привязки. Схема не изменяется; оценки Jev требуют проверки человеком.

## Как это работает

```
 Веб-интерфейс (bpmn-js): ввод описания · холст bpmn.io · диалог правок · отчёт · экспорт
        │ текст                                   ▲ BPMN XML      │ просьба + текущий XML
        ▼                                          │               ▼
 ┌─ Backend (FastAPI) ──────────────────────────────────────────────────────────────────┐
 │ [LLM] Планировщик  текст → JSON-план ──(pydantic + ссылки; ошибка → самоисправление ≤2)│
 │ [LLM] Генератор    JSON-план → Python-код на DIAGRAM API                               │
 │        ▲  repair-loop ≤3: ошибка песочницы / семантики / XSD → обратно в LLM           │
 │ Песочница        AST-whitelist, пустые builtins, таймаут, бюджет операторов           │
 │ Граф DIAGRAM     узлы, потоки, пулы, дорожки, группы, подпроцессы                      │
 │ Нормализация     безопасные автоисправления (дубли, связи между пулами → сообщения…)  │
 │ Валидатор        достижимость, обрывы, шлюзы, deadlock, подписи ветвей…                │
 │ Раскладка        Sugiyama с учётом дорожек, ортогональная трассировка, циклы в коридоре│
 │ Сериализатор     BPMN 2.0 XML + BPMN DI (+ отдельные планы для подпроцессов)           │
 │ XSD              проверка по официальной схеме OMG BPMN20.xsd                          │
 │ Fallback         компилятор план→код (детерминированный) → мягкий режим               │
 │ Импорт XML→код   ручные правки из bpmn.io превращаются обратно в код для диалога       │
 └────────────────────────────────────────────────────────────────────────────────────────┘
        │ журнал прогонов runs/…                       eval/run_eval.py — перезапуск и метрики
```

Подробно об архитектуре, решениях и отличиях от исходной схемы — в [docs/architecture.md](docs/architecture.md).
Описание программного интерфейса — в [docs/api.md](docs/api.md).

## Возможности

- **Участники**: дорожки в пуле организации; внешние организации — отдельные пулы (в том числе
  «чёрный ящик») с потоками сообщений.
- **Элементы**: задачи 8 типов (user, service, send, manual…), шлюзы (исключающий, параллельный,
  инклюзивный, событийный), события старта и окончания и промежуточные события (таймер, сообщение,
  ошибка, terminate), свёрнутые подпроцессы с проваливанием внутрь в bpmn.io, группы, аннотации.
- **Ветвления и циклы**: подписанные условия, параллельные ветви, возвраты на доработку.
- **Надёжность**: repair-loop — модель видит свой код и точный текст ошибки со строкой. Если модель
  не справилась, план компилируется детерминированно; в крайнем случае схема строится в мягком
  режиме с автоисправлениями. Аналитик всегда получает открываемый файл и список замечаний.
- **Проверки**: XSD BPMN 2.0, семантический валидатор (недостижимые узлы, обрывы, deadlock при
  слиянии исключающих ветвей параллельным шлюзом, лишние шлюзы, неподписанные ветви), импорт в
  bpmn-js без предупреждений (в UI и в eval).
- **Для аналитика**: допущения ассистента и *вопросы к заказчику* по неясным местам описания;
  клик по замечанию подсвечивает элемент на схеме.
- **Связь текста и схемы**: точные фразы в описании подсвечивают шаги на схеме и наоборот;
  отдельная проверка показывает, что осталось без связи. История версий помогает откатить правки.
- **Навигация по большой схеме**: быстрый поиск шагов и фокус по участнику помогают найти нужный
  участок без изменения BPMN; связанные с фразами блоки выделяются заливкой.
- **Диалог**: «объедини проверки в подпроцесс», «добавь согласование юристом». Изменения вносятся
  в код, ручные правки на холсте сохраняются благодаря импорту XML→код.
- **Экспорт**: `.bpmn`, SVG, PNG. Импорт любого `.bpmn` с пересчётом раскладки.
- **Журнал и eval**: каждый прогон сохраняется в `runs/` (запросы, ответы LLM, код всех попыток,
  ошибки, файл). Eval-стенд перезапускает пайплайн и считает метрики.

## Примеры

Примеры лежат в [`examples/`](examples). В каждой папке: `input.txt` — описание, `plan.json` — план,
`code.py` — код на DIAGRAM API, `result.bpmn`, `result.png`/`.svg`, `report.json` — проверки,
допущения и вопросы.

| Пример | Участники | Что показывает |
|---|---|---|
| [01_credit](examples/01_credit) — выдача кредита | 6 дорожек + внешнее БКИ | цикл дозаполнения, параллельные проверки, ветвление по сумме, отказ |
| [02_eshop](examples/02_eshop) — заказ в интернет-магазине | 5 дорожек + банк | пропуск шага по условию, параллельная сборка/документы, возврат |
| [03_grid_connection](examples/03_grid_connection) — техприсоединение к электросетям | 5 дорожек + подрядчик | подпроцесс, два параллельных блока, цикл устранения замечаний |
| [04_hiring](examples/04_hiring) — подбор сотрудника | 5 дорожек | инклюзивный шлюз, цикл отбора, отказ кандидата |
| [05_outage](examples/05_outage) — аварийное отключение | 4 дорожки | параллельное SMS-уведомление, цикл с резервным питанием |

> Как получены примеры: в этом репозитории `plan.json` — эталонные планы, составленные вручную в
> формате ответа планировщика. По ним детерминированная часть пайплайна собрала `code.py` и
> `result.bpmn`. Чтобы получить те же файлы через LLM, запустите
> `python scripts/build_examples.py --llm --render`. Полный прогон через модель с метриками —
> `python eval/run_eval.py`.

## Проверка качества

```bash
cd backend && python -m pytest -q          # 31 тест: песочница, валидатор, раскладка, XSD, импорт, repair-loop
python eval/run_eval.py --offline --render # детерминированная часть на эталонных планах + bpmn-js
python eval/run_eval.py --modes two_stage direct --render   # полный пайплайн через LLM, сравнение режимов
```

Eval считает по каждому кейсу: построено ли, XSD, открывается ли в bpmn-js без предупреждений,
сколько было раундов repair-loop, откуда взят результат (с первой попытки / после исправлений /
fallback), время и структурный балл (найдены ли ожидаемые участники, типы шлюзов, количество
задач, циклы). Отчёт сохраняется в `eval/results/*.md|json`.

## Ограничения

- Раскладка строится по слоям и дорожкам. На очень больших схемах (больше 60 элементов) она
  получается широкой: такие процессы лучше разбивать на подпроцессы (планировщик предлагает это сам).
- Подпроцессы только свёрнутые: содержимое открывается проваливанием в bpmn.io. Граничные
  события (boundary), объекты данных и хранилища пока не поддерживаются. При импорте граничные
  события превращаются в промежуточные.
- Группы при импорте XML→код не сохраняются. Раскладка после импорта пересчитывается, и ручное
  расположение элементов не сохраняется (сохраняется структура).
- Качество плана зависит от модели. Слабые модели чаще ошибаются в типах шлюзов; часть таких ошибок
  ловит валидатор (deadlock, лишние шлюзы), и они исправляются в repair-loop.
- Условия ветвей записываются как текст (`conditionExpression` = подпись). Исполняемых выражений
  для движка процессов нет: схема предназначена для анализа, а не для исполнения (`isExecutable=false`).

## Структура

```
backend/app/
  bpmn/diagram.py     DIAGRAM API и граф процесса
  bpmn/validator.py   нормализация и семантическая валидация
  bpmn/layout.py      раскладка с пулами и дорожками, трассировка связей
  bpmn/serializer.py  BPMN 2.0 XML + DI
  bpmn/xsd.py         проверка по XSD (schemas/ — официальные XSD OMG)
  bpmn/importer.py    BPMN XML → код DIAGRAM
  llm/                клиенты LLM, промпты, JSON-план и его компилятор
  sandbox.py          AST-фильтр и выполнение кода
  pipeline.py         оркестрация, repair-loop, fallback
  runlog.py           журнал прогонов
  main.py             FastAPI
frontend/             UI на bpmn-js (вендорная сборка, без шага сборки)
examples/             входные описания и результаты
eval/                 eval-стенд
tools/render.mjs      импорт в bpmn-js и рендер PNG/SVG в headless Chromium
scripts/build_examples.py
```
