# Ограничения

Ниже то, что не сделано или сделано упрощённо, без приукрашивания.

## Проверка на реальных моделях
- Сценарии с моделью покрыты тестами с замоканным LLM. Сетевые вызовы проверены на настоящих
  endpoint Gemini и OpenAI-совместимых с фиктивными ключами: проверялись формат запросов, ошибки и
  откат режимов. На gpt-oss-120b, Qwen3 и Yandex AI Studio с рабочим ключом пайплайн при разработке
  **не запускался**. Перед защитой прогоните `python eval/run_eval.py --render` на целевой модели и
  при необходимости донастройте промпты (новые версии в `backend/app/prompts/`).
- Неизвестно, поддерживает ли конкретный endpoint Yandex `response_format: json_schema`. Если нет,
  адаптер сам переходит на `json_object`, затем на JSON по промпту и запоминает выбор
  (`LLM_JSON_MODE`).
- Примеры `examples/*` собраны из эталонных IR, написанных вручную, а не моделью (это указано в README).

## BPMN и раскладка
- Раскладка своя (слоевая, с дорожками), не ELK. На процессах больше ~60 элементов схема
  получается широкой; такие процессы лучше разбивать на подпроцессы. Пересечения связей в сложных
  случаях возможны (узлы не перекрываются — это проверяется тестом).
- Подпроцессы только свёрнутые (содержимое открывается проваливанием в bpmn.io).
- Граничные события — только таймеры (SLA и эскалация). Граничные события ошибок и сообщений,
  объекты данных, хранилища, хореографии и диаграммы взаимодействия не поддерживаются. При импорте
  чужих BPMN такие граничные события становятся промежуточными.
- При импорте BPMN раскладка пересчитывается: структура сохраняется, ручное расположение — нет.
  Группы при обратной конвертации BPMN → IR сохраняются, аннотации — нет.
- Условия ветвей — текст (`conditionExpression` = подпись). Схема предназначена для анализа, а не
  исполнения (`isExecutable=false`). Экспорт «Camunda 8» — заготовка: FEEL-условия и воркеры
  настраивает инженер.

## Аналитика
- Без реальных логов все длительности — данные аналитика, оценки модели или типовые значения.
  Результаты симуляции описывают модель процесса, а не реальность; оценки помечаются.
- Симуляция не учитывает ограничения ресурсов (очереди к одному исполнителю, календари): загрузка
  считается как доля рабочего времени участника в общем времени процесса.
- Вероятности ветвей без явного задания делятся поровну.
- Тест-пути: циклы проходятся не больше одного раза, OR-развилки — до 4 ветвей, по умолчанию
  не больше 40 сценариев (до 200).
- RACI: буквы A, C, I, которых нет в IR, выводятся эвристически (руководитель по названию
  дорожки, следующий исполнитель, получатель сообщения) и помечаются.

## Тексты и данные
- Маскирование ПДн — регулярные выражения, без NER. ФИО распознаются только в формах «Фамилия Имя
  Отчество», «Фамилия И. О.», «И. О. Фамилия»; одиночная фамилия не маскируется. Адреса и
  энергообъекты по умолчанию не маскируются.
- PDF без текстового слоя (сканы) не распознаются — нужен OCR.
- Слияние частей длинного документа предполагает, что части идут последовательно. Если процесс в
  документе описан не по порядку, связи между частями нужно проверить вручную.
- Объяснение процесса и рекомендации модель формирует по IR. Фактов вне IR в них быть не должно, но
  это не гарантируется: рекомендации помечены как «рекомендация, не факт».

## Не делалось (по границам задания)
Конструктор форм, объектная модель, исполнение процессов (движок), CRM, RPA, мобильное приложение,
роли и авторизация.

## Не успели
- RAG по корпоративным регламентам (подсказки терминов и проверка соответствия).
- Отдельная модель для каждого шага пайплайна. Сейчас можно выбрать только отдельную модель для
  самоисправления (`LLM_REPAIR_MODEL`).
