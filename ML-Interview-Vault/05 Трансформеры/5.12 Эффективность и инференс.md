# 5.12 Эффективность и инференс LLM ⭐⭐⭐

## Две фазы инференса
```
 Prefill:  весь промпт за один проход, параллельно → compute-bound (GPU занят матричными умножениями)
           → метрика TTFT (time to first token)
 Decode:   по одному токену; каждый шаг читает ВСЕ веса и KV-кэш → memory-bandwidth-bound
           → метрика TPOT / tokens per second
```

## KV-cache ⭐⭐⭐
Без кэша на каждом шаге генерации пересчитываем K и V **для всех предыдущих токенов** → $O(n^2)$ лишней работы. Но K,V прошлых токенов **не меняются** (causal mask!) → **кэшируем**, на новом шаге считаем Q,K,V только для нового токена.
```
 Шаг t:   q_t ──attention──▶ [k₁ k₂ … k_{t-1} | k_t]   ← из кэша + новый
                             [v₁ v₂ … v_{t-1} | v_t]
```
**Размер кэша**: $2\times n_{layers}\times n_{kv\_heads}\times d_{head}\times L\times\text{batch}\times\text{bytes}$.
Пример LLaMA-2 7B (32 слоя, 32 головы, 128, FP16), 4096 токенов: $2\cdot32\cdot32\cdot128\cdot4096\cdot2\text{B} = 2$ GB **на одну последовательность**.
Уменьшение: **GQA/MQA** ([[5.2 Multi-Head Attention и маски]]), MLA, квантизация KV, sliding window, **PagedAttention**.

## FlashAttention ⭐
Проблема: стандартный attention материализует матрицу $n\times n$ в медленной HBM-памяти GPU → упирается в **пропускную способность памяти**.
Решение: **tiling** — считаем attention блоками в быстрой SRAM, **online softmax** (пересчёт нормировки на лету), не сохраняем $n\times n$ (на backward пересчитываем).
✅ **Точный** (не приближение!) результат, память $O(n)$ вместо $O(n^2)$, в 2–4× быстрее. FlashAttention-2/3.

## PagedAttention (vLLM)
KV-кэш хранится **страницами** (как виртуальная память ОС) → нет фрагментации, sharing префиксов, большой батч. + **Continuous batching**: новые запросы добавляются в батч по мере завершения старых (а не ждём весь батч).

## Квантизация ⭐
Храним веса (и/или активации) в меньшей точности.
| Формат | Байт/параметр | 7B модель |
|---|---|---|
| FP32 | 4 | 28 GB |
| FP16/BF16 | 2 | 14 GB |
| INT8 | 1 | 7 GB |
| INT4 | 0.5 | 3.5 GB |
$q = \text{round}(w/s) + z$ (scale, zero-point); по тензору / каналу / **группе** (group-wise, 64–128).
- **PTQ** (post-training): **GPTQ** (по слоям, компенсация ошибки через гессиан), **AWQ** (защищает «важные» каналы по активациям), SmoothQuant (W8A8 — переносит выбросы активаций в веса), **GGUF** (llama.cpp, CPU), bitsandbytes (LLM.int8 — выбросы в FP16).
- **QAT** (quantization-aware training) — точнее, дороже.
- Проблема: **выбросы (outliers)** в активациях больших моделей.
- FP8 — на H100 и для обучения.

## Speculative decoding ⭐
Маленькая **черновая** модель быстро генерирует $k$ токенов → большая **проверяет их за один проход** (параллельно) → принимает префикс совпадений (rejection sampling сохраняет **точное** распределение большой модели). Ускорение 2–3×. Варианты: Medusa (несколько голов), EAGLE, lookahead.

## Mixture of Experts (MoE) ⭐
FFN заменяется на $E$ экспертов + **роутер** выбирает top-k (обычно 1–2 из 8–256) для каждого токена.
```
 token → [Router] ──▶ Expert 3 ─┐
                └──▶ Expert 7 ─┴─(взвешенная сумма)─▶
          (остальные эксперты не считаются)
```
✅ Параметров много (знания), **вычислений — как у маленькой** (Mixtral 8×7B: 47B всего, ~13B активных). ❌ Вся модель в памяти, балансировка нагрузки (auxiliary loss), коммуникации. Примеры: Mixtral, DeepSeek-V3 (671B / 37B активных), Qwen-MoE, GPT-4 (по слухам).

## Длинный контекст и эффективный attention
- **Sparse attention** (Longformer, BigBird: локальное окно + глобальные токены).
- **Sliding window** (Mistral).
- **Linear attention** (Performer, Linformer) — $O(n)$, приближение.
- **Ring attention** — распределение по устройствам.
- **SSM / Mamba**, гибриды (Jamba) — линейная сложность.
- RoPE scaling (YaRN) → [[5.3 Позиционное кодирование]].
- Проблема **lost in the middle**: модель хуже использует середину длинного контекста.

## Прочее
- Прунинг (SparseGPT, Wanda), дистилляция в маленькие модели.
- **Prefix/prompt caching** — переиспользование KV общего системного промпта.
- Фреймворки: **vLLM**, TGI, TensorRT-LLM, SGLang, llama.cpp, Triton Inference Server.
