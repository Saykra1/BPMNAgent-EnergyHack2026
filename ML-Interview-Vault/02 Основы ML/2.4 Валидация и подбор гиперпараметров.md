# 2.4 Валидация и подбор гиперпараметров

## Train / Validation / Test
```
|────────── train (60–80%) ──────────|── val (10–20%) ──|── test (10–20%) ──|
   обучаем параметры                  подбираем гиперпар.   финальная оценка
                                       и early stopping      (трогаем 1 раз!)
```
Если подбирать гиперпараметры на test — он перестаёт быть честной оценкой (overfitting to test).

## Кросс-валидация (k-fold)
```
Fold 1: [VAL][trn][trn][trn][trn]
Fold 2: [trn][VAL][trn][trn][trn]
Fold 3: [trn][trn][VAL][trn][trn]
Fold 4: [trn][trn][trn][VAL][trn]
Fold 5: [trn][trn][trn][trn][VAL]
        → среднее ± std метрики
```
| Вариант | Когда |
|---|---|
| **K-Fold** (k=5/10) | стандарт |
| **Stratified K-Fold** | классификация, особенно дисбаланс — сохраняет доли классов |
| **Group K-Fold** | несколько объектов одного клиента → все в одном фолде (иначе утечка!) |
| **TimeSeriesSplit** | временные ряды: train всегда **раньше** val |
| **LOO** (leave-one-out) | очень мало данных; дорого, высокая дисперсия оценки |
| **Nested CV** | честная оценка при подборе гиперпараметров (внешний цикл — оценка, внутренний — подбор) |

```
TimeSeriesSplit (expanding window):
 [trn][val]
 [trn trn][val]
 [trn trn trn][val]
 [trn trn trn trn][val]   → время →
```

## Утечки данных (Data Leakage) ⭐
Информация из val/test или «из будущего» попадает в обучение → метрики завышены, в проде всё плохо.
- Масштабирование / импутация / target encoding **на всём датасете** до сплита → делать **внутри фолда** (`sklearn.Pipeline`).
- Признаки, которые недоступны в момент предсказания (например, «дата закрытия кредита» при предсказании дефолта).
- Дубликаты объектов в train и test.
- Случайный сплит временных данных.
- Один клиент в train и test (нужен GroupKFold).
- Отбор признаков на всех данных.

## Подбор гиперпараметров
| Метод | Суть | Плюсы/минусы |
|---|---|---|
| **Grid Search** | перебор сетки | прост, экспоненциально дорог |
| **Random Search** | случайные точки | эффективнее grid, когда важны лишь некоторые параметры (Bergstra & Bengio) |
| **Bayesian Optimization** (Optuna/TPE, GP) | суррогатная модель $p(\text{score}|\theta)$ + acquisition (EI) | меньше итераций |
| **Hyperband / ASHA** | раннее отсечение плохих конфигураций | быстро для DL |
| **Population Based Training** | эволюция + обмен весами | большие DL |

```
Grid search             Random search
 · · · · ·               ·    ·  ·
 · · · · ·                 ·   ·    ·
 · · · · ·               ·   ·   ·
 (5 уникальных значений  (15 уникальных значений
  важного параметра)      важного параметра)
```

## Ранняя остановка (early stopping)
Следим за val-лоссом, останавливаемся, если он не улучшается `patience` эпох, восстанавливаем лучшие веса.

## Адверсариальная валидация
Обучаем классификатор отличать train от test. Если AUC ≫ 0.5 — распределения различаются (covariate shift); смотрим важные признаки, строим val похожим на test.
